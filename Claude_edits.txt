EDIT 5 — Headlight direction: imap → map and correct camera-space direction
File: neuronvis/hoc_graphics.py  (_update_light_dir and attach_headlight)
Reason: Two bugs in the headlight direction computation:

  Bug A — wrong transform operation:
    camera.transform maps FROM camera space TO scene space (it is the camera's
    node transform in vispy's scene graph, not the view matrix).
    Therefore transform.map(cam_dir) gives the scene-space equivalent of cam_dir.
    We were using transform.imap(...) which goes the opposite direction
    (scene→camera), giving a nonsensical scene-space direction.
    This matches the official vispy mesh_shading.py example which uses .map().

  Bug B — wrong camera-space direction:
    For vispy's ArcballCamera with up='+z', the camera looks in the scene +Y
    direction (forward=(0,1,0)). The "behind camera / toward viewer" direction
    in camera space is therefore -Y = [0,-1,0,0].
    We were using [0,0,1,0] (scene +Z) which is unrelated to the viewing direction.

Old code:
    self._cam_space_light = np.array([0, 0, 1, 0], dtype=float)
    direction = self.view.camera.transform.imap(self._cam_space_light)[:3]

New code:
    self._cam_space_light = np.array([0, -1, 0, 0], dtype=np.float32)
    direction = self.view.camera.transform.map(self._cam_space_light)[:3]

Comment: # Claude fixed 2026-06-16: imap (scene→camera) was wrong; camera.transform
         # maps camera→scene, so map() is correct (matches vispy mesh_shading example).

EDIT 6 — Junction spheres at branch points (vispy only)
File: neuronvis/hoc_graphics.py  (new method build_junctions, __init__, _update_light_dir)
Reason: Where two angled cylinders meet at a branch point, the flat end-caps of
each TubeVisual do not align perfectly, leaving visible wedge gaps. Placing a
sphere at the parent section's last pt3d hides these gaps.

Changes:
  1. Added self.vspheres = [] in __init__, after self.vtubes = [].
  2. Added self.build_junctions() call after the tube-creation loop.
  3. Added loop "for sphere in self.vspheres: view.add(sphere)" after the vtubes loop.
  4. New method build_junctions() — two passes:
     Pass 1 (junction spheres): for each section that has a parent, place one Sphere
       at the parent section's last pt3d. Deduplicated by parent section name so
       branch points with multiple children get only one sphere.
     Pass 2 (terminal end-cap spheres): for every leaf section (no children), place a
       Sphere at its last pt3d to seal the open tube end.
  5. Sphere radius: max(diam / 2.0 * 0.95, 0.05).  The 0.95 factor avoids slight
     protrusion beyond the tube wall; the 0.05 floor prevents failure on
     zero-diameter sections.
  6. Color: looked up from self.section_colors (same dict as tubes).
  7. Parameters: cols=12, rows=12, shading="smooth".
  8. Creation wrapped in try/except to tolerate degenerate sections silently.

Comment: # Claude fixed 2026-06-16: junction/terminal spheres fill gaps at branch points

EDIT 7 — Terminal end-cap sphere: outward direction offset
File: neuronvis/hoc_graphics.py  (build_junctions, terminal pass)
Reason: Sphere centered exactly at the tube endpoint is half-buried inside the
tube, causing z-fighting between the sphere back-face and the TubeVisual's flat
end-cap disc — some terminal caps appeared missing at certain viewing angles.
Fix: Offset the sphere centre 10% of its radius outward along the terminal
segment direction vector (from pt3d[n-2] → pt3d[n-1]):
    dx, dy, dz = direction vector
    seg_len = ||d||
    x += dx/seg_len * radius * 0.1   (and similarly y, z)
Only applied when n3d >= 2 (there is a direction to compute).

Old code: sphere centered at (sec.x3d(li), sec.y3d(li), sec.z3d(li))
New code: same point offset by radius*0.1 in terminal-segment direction

EDIT 8 — Sphere headlight: SphereVisual CompoundVisual._mesh fix
File: neuronvis/hoc_graphics.py  (_update_light_dir)
Reason: Spheres were not responding to the headlight — they stayed statically lit
while tubes tracked the camera correctly.
Root cause: SphereVisual inherits from CompoundVisual. Its actual MeshVisual
lives in sphere._mesh, not on the SphereVisual itself. Therefore:
  sphere.shading_filter  →  None    (no shading_filter on CompoundVisual)
  sphere._mesh.shading_filter  →  ShadingFilter instance  (correct)
TubeVisual inherits directly from MeshVisual, so tube.shading_filter works
without indirection.

Old code (only iterated vtubes):
    for visual in self.vtubes:
        sf = getattr(visual, "shading_filter", None)

New code (iterates both, handles CompoundVisual indirection):
    for visual in (*self.vtubes, *self.vspheres):
        mesh_vis = getattr(visual, "_mesh", visual)
        sf = getattr(mesh_vis, "shading_filter", None)
        if sf is not None:
            sf.light_dir = direction
